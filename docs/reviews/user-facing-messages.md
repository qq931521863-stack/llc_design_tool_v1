# 用户提示与设计校核文案检查

本次检查覆盖 LLC、PFC、Control Tools、FRA 桌面界面及网页端，重点搜索
`FAIL`、`不可行`、`参数错误`、`禁止`、异常弹窗和直接显示的英文诊断。

## 已调整

- LLC 结果总览：区分计算完成与约束满足，取消总体 `FAIL / 不可行原因` 表述。
- LLC 常见约束：保持时间、母线末端电压、磁芯气隙、窗口填充、磁通、温升、
  器件耐压、ZVS、纹波及增益不可达，提供中文说明与检查方向。
- 未识别的新诊断：明确要求复核并保留原文，不静默丢弃，也不显示为成功。
- LLC、PFC、Control Tools、FRA 的常见参数、文件、计算和代码生成异常：
  使用温和标题、操作指引与可展开的原始技术详情。实际异常仍保留原严重程度。
- 自动设计未满足约束、控制器不稳定：说明暂不能应用/导出的原因和下一步，
  保留原阻止条件。
- 网页 LLC：黄色设计提醒、中文约束说明、可展开的原始信息。
  API 原有 `status`、`feasible`、`feasibility_reasons` 不变，新增 `design_notes_zh`。

## 文案原则

先交代本次操作是否完成，再说明具体差距，最后给出可以执行的下一步。
不用“不要担心”“一定能成功”等无依据保证；不将额定值或稳定性问题说成无关紧要。
数值、单位和约束含义必须保留；部分工况未求解时，不暗示全部工况已经验证。

## 边界与后续检查点

这次调整针对总体状态与常见操作入口，并非全部产品文本的完整本地化。
器件库的部分独立弹窗、材料参考说明、详细数值表、导出报告、CLI 与底层诊断
仍可能显示英文或 PASS/FAIL。具体电压、电流和稳定性检查的失败语义不能简单
替换成“成功”；后续可逐项改成“裕量不足”“尚未收敛”等准确表述。
新增详细解释以中文为主，非中文界面的技术诊断仍保留英文。
